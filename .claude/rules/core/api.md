# Core

- The root entry has only `reveal`, `cascade` and their types. Adapter machinery (`createReveal`, `createCascade`, the hidden attributes, the adapter options with `when` and `onReveal`) stays in `src/adapter.ts`, behind `@awesome-reveal/core/adapter`. Do not re-export it from `src/index.ts`. The package `dist.test.ts` and `tree-shaking.test.ts` check this boundary.
- Do not add options, aliases or helpers to the imperative API. The API is frozen: `from` or native `keyframes`, `duration`, `threshold`, and `interval` for `cascade`. Each entrance plays once: there is no `once` option, because a reset on exit made the observer see the start state and loop at the viewport edge. Advanced motion uses native `Keyframe[]`, which wins over `from` at runtime. Generated keyframes stay internal in `src/animation.ts`.
- Imperative core needs no CSS. `motion()` creates a paused animation with `fill: "backwards"` at `currentTime = 0`, so the first keyframe hides the element before it enters the viewport. `play()` runs the animation only while it is paused, so a page `finish()` or `cancel()` before the entry wins. Do not rewind it, and keep the reference, so that `dispose()` still cancels an animation that page code started. Do not inject a `<style>` and do not import CSS from a core module. SSR pre-hiding belongs to the adapters.
- The generated entrance uses individual `translate`, `scale`, `rotate` and `filter` with `composite: "add"` and neutral end values, so it composes with the element's own styles and has no implicit keyframe, which is not Baseline. Do not use an additive `transform` list: an author `scale(2)` doubles the offset. The opacity start is a separate replace keyframe, because Firefox and WebKit clamp a negative additive opacity before the addition. Chromium does not composite an effect with an additive keyframe. This cost is accepted for composability, and native `keyframes` are the composited escape hatch.
- A start state with opacity 0 holds neutral values at offset 0, and its move keyframe is at offset `1e-6`. IntersectionObserver measures the transformed box, so a waiting offset can put a small element fully outside an `overflow` ancestor, and the element never reveals. The move starts while the element is transparent, so it is not visible. Other start states keep the move at offset 0, because a move at the play would jump visibly. These start states and native keyframes can still stay hidden in a clipping ancestor. The README documents this limit. A full fix needs a box that the entrance cannot move, such as the parent or an added element, and core rejects both. The adapters do not have this limit: their CSS hides with opacity only, and the animation starts at the reveal.
- Every failure leaves content visible. A throw from `animate()`, from the observer constructor or from `observe()` reveals at once. `dispose()` cancels the animations, so the elements go to their resting style. Do not add runtime validation for values that the browser validates.
- Reduced motion is automatic and has no option. When `prefers-reduced-motion: reduce` matches, `reveal` and `cascade` create no animation, and a later change to `reduce` disposes them.
- Print has no stylesheet in core, so `beforeprint` moves each paused animation to its end time, past its backwards fill, and `afterprint` sets it back to 0. Only paused animations change, so a playing entrance is not rewound. The adapters need no print handler: their `reveal.css` has a print rule, and they create the animation only at the reveal. A real print in Chromium, also `page.pdf()` of Playwright, fires both events; `emulateMedia({ media: "print" })` fires none.
- `cascade` observes each container and animates its direct element children with `delay = index * interval`. It reads the children once, when it starts. Do not clamp a negative `interval`: WAAPI accepts a negative delay, which starts later children further into their entrance. Do not add a child selector or a timeline abstraction.
- `observe` uses the thresholds `[0, threshold]`, and also reveals an element that leaves the root before it reaches `threshold`. An element larger than the root cannot reach a high threshold. A clamp from `rootBounds` was rejected: it fails in scroll containers, after the element grows and with a large start offset.
- Do not throw when an API is missing. Without IntersectionObserver, reveal at once. Without `Element.animate`, reveal with no animation.
- Do not use `window` or `document` at module level. Server renderers import core. A selector resolves to no elements when `document` is undefined.
- The `.d.ts` files carry the JSDoc, and the JS output has none. Write the option docs and defaults in the type JSDoc.
- A consumer bundle of an adapter includes core. The tree-shaking tests measure the core code in that bundle, so new code in `animation.ts`, `observe.ts` or `adapter.ts` counts against the size limits of all adapters.

## Adapter store

- `createReveal` and `createCascade` share one store. It owns the state: the observer, `when ?? inView` and the play. It changes no DOM, except `data-reveal-ready` on `<html>`. The adapter renders `data-reveal` from `revealed`.
- Start `play` in the same task that removes `data-reveal`. Between the two, the element shows at full opacity, because `fill: "backwards"` applies the first keyframe only after `play` creates the animation.
- Hide in this order: cancel the animation, then tell the listener. Reveal in this order: tell the listener, then `play`, in the same task.
- `setOptions` replaces the options and does not merge them. Only a change of `when` or `threshold` restarts the observer. `createReveal` copies the options, because a directive can pass the same mutated object again.
- `when == null` means that the viewport decides. Use `??` and `== null`, not default values, because defaults do not apply to `null`.
- A revealed state plays once. `revealed` starts `false`, also with `when: true`, so that the server renders the element hidden. The first `attach` reveals and plays the entrance. A new element keeps the state and does not play again.
- `report()` in `src/report.ts` throws from a microtask, once for each message on a page. A throwing `onReveal` and the errors that `motion()` and `observe()` catch go to it. Do not report once per call: adapters create the motion at reveal time, so a list of components would report once per item. Do not throw from `observe`, `play` or `createReveal`, because a render or an effect can call them, and an uncaught error in a React effect unmounts the root. Tests that touch a report stub `queueMicrotask`.
- The behavior spec of the adapters is the contract suite in `packages/test-utils` (`contract.ts`, `contract-ssr.ts`). Change a behavior there first, so that all adapters follow. A framework adapter cannot add behavior that core does not have.
- A cascade store reads the children in `play`, at the reveal, and not at `attach`, so children that the framework renders after the attach also animate. Imperative `cascade()` reads them when it is called. The adapter cascade hides the children, not the container: `[data-reveal="cascade"] > *`. With a hidden container, its background and border pop in with no animation. A child with `display: contents`, such as an Astro island or host, gets no visible entrance.
- Each adapter renders the hidden markup itself, with `hiddenAttributes` or `cascadeHiddenAttributes`, and ships its own `reveal.css`. The CSS hides `[data-reveal="hidden"]` and `[data-reveal="cascade"] > *`, and shows them again with reduced motion, with JavaScript off, in print and under `html[data-reveal-failed]`. The library writes no inline style, so a strict CSP needs no `'unsafe-inline'`. `data-reveal` is reserved.
- The first `attach` sets `data-reveal-ready` on `<html>`. A recovery script of the application can read it, and set `data-reveal-failed` when the client script does not start.
